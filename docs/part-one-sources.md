## Semantics that must remain exact

- Words are 16 bits. Add16, Inc16, and ALU wrap modulo 65536. Signed interpretation is two's complement, from -32768 to 32767; carry-out and signed overflow are different concepts. Hack ALU has no overflow output.
- Apply ALU controls in order: zero and optionally invert each input, choose bitwise AND or addition, optionally invert the result, then derive `zr` and `ng` from the final 16-bit result. Six controls define 64 combinations, with 18 named functions documented in Chapter 2.
- Clocked chips sample and commit state together. In official `Bit.tst`/`Bit.cmp`, `tick` observations show the previous value; the following `tock` exposes the committed value. A combinational feedback loop remains invalid, while feedback crossing a state element is meaningful.
- RAM reads follow the selected address without a clock. A write captures its address, input and load for the next state transition; changing the address must not move a pending write. PC priority is reset, then load, then increment, then hold.
- `M` denotes the word addressed by A. CPU `outM`/`writeM` are combinational; `addressM` and `pc` reflect clocked state. Consequently, when a C-instruction changes A and also writes M or jumps, the current memory address and jump destination use the old A. This is a consequence of the documented simultaneous register-update model, not a sequential software assignment order.
- CPU reset redirects the next PC to zero; it is not a command to clear all registers and RAM. Chapter 5's PDF has an inverted parenthetical comment on the reset input; the surrounding prose and current `CPU.hdl` specify reset=1 as restart.
- Data RAM occupies 0–16383. Screen words occupy 16384–24575. Keyboard is the read-only word at 24576. Addresses above that are invalid according to `Memory.hdl`; do not invent ordinary RAM there. ROM has 32768 instruction addresses and is separate from data memory.
- Screen geometry is 512×256, with 32 words per row and bit 0 at the left of each 16-pixel word. Keyboard zero means no key; browser keyboard input should map to Hack codes rather than silently using unrelated browser key codes.
- A C-instruction has the layout `111accccccdddjjj`. The book presents canonical destination spellings such as `MD`; official Project 6 fixture programs also use `DM`. Accept unique A/D/M destination letters in either order, mapping them to the same destination bits, while rejecting duplicates and other letters.
- Assembly is case-sensitive. Labels emit no words and denote ROM addresses; variables occupy RAM addresses beginning at 16. A-instruction literals occupy 15 bits. Reject invalid input with line-specific errors and clear stale executable output rather than silently truncating it.

## Official web IDE tool inventory

The expanded tool scope was checked against the [official web IDE](https://nand2tetris.github.io/web-ide) and its [source repository](https://github.com/nand2tetris/web-ide), pinned at `2070cd89065e49074563b33c7ca066d953aa8a8a`. The six entries are declared in [`web/src/urls.tsx`](https://github.com/nand2tetris/web-ide/blob/2070cd89065e49074563b33c7ca066d953aa8a8a/web/src/urls.tsx). `/util` and `/about` are supporting pages, not additional simulator types.

| Upstream tool      | Chips and Code surface | Required behavior and useful integration check                                                                                                                                                                                                                             |
| ------------------ | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hardware Simulator | `/tools/chip-builder`  | Compile learner HDL, connect buses and custom chips, evaluate signals, separate tick/tock state, load ROM and inspect mapped memory, and run bounded TST scripts against optional CMP output. A compiled Computer probe must execute a ROM program and change its own RAM. |
| CPU Emulator       | `/tools/computer`      | Load assembly or binary, step/run/reset, show A/D/PC and memory, screen and keyboard devices. A program must visibly update RAM and obey a jump.                                                                                                                           |
| Assembler          | `/tools/computer`      | Translate Hack assembly, expose binary words and source mapping, resolve labels and variables, export `.hack`, report invalid input without keeping stale executable code. This shares a focused workspace with the CPU emulator.                                          |
| VM Emulator        | `/tools/vm`            | Parse and execute real VM instructions, show stack and segments, support multiple files and function calls, and expose screen/keyboard through the supplied OS services. Validate arithmetic, call/return, and compiler output.                                            |
| Jack Compiler      | `/tools/compiler`      | Compile Jack source to VM, report syntax/semantic errors, preserve source drafts, and transfer successful output to the VM. Validate an actual compiled program instead of only checking that text was produced.                                                           |
| Bitmap Editor      | `/tools/bitmap`        | Edit pixels and generate usable Hack/Jack drawing code. Bit 0 must remain the leftmost pixel of a word. Export must handle signed 16-bit values, including the `0x8000` case, and use a 32-word screen stride.                                                             |
