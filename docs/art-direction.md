# Chips and Code: visual direction

## Identity

Use the original Chips and Code logo assets and indigo `#4f46e5`. The product remains Chips and Code. The redesign should feel precise, capable, and intriguing: an interactive machine that exposes its structure. Technical details are part of the visual identity, not decorative text scattered over a generic game skin.

## A computer as the world

The main visual is an exploded stack of computer layers. Its dark foundation represents binary signals and gates. Increasingly light upper layers represent abstraction: arithmetic, memory, architecture, and software. Labels explain what each layer contributes. Planned layers remain clearly marked and cannot imply a playable editor that does not exist.

Use connected traces, silicon-like surfaces, register rows, instruction patterns, and code only where they reinforce the role of the layer. Make the ordering and dependency legible. The current logic layer contains the real gate sequence and reflects saved verification state.

The result should feel closer to a schematic, instrument panel, or software development environment than a miniature landscape. Avoid fictional place names, collectible gems, mascots, scenery, and unrelated reward metaphors.

## Palette and material

| Role                  | Color     |
| --------------------- | --------- |
| Deep background       | `#0b0d14` |
| Working surface       | `#12151f` |
| Primary text          | `#f0f0f7` |
| Secondary text        | `#a1a5b6` |
| Dividers              | `#303446` |
| Original brand        | `#4f46e5` |
| Bright signal / focus | `#a79fff` |

Use restrained indigo illumination against dark neutral surfaces. Higher stack layers introduce pale surfaces as a meaningful shift in abstraction. Keep the workbench low-glare and high-contrast. Active signals must include readable `0`/`1` values and names; glow alone is insufficient.

Small corner radii, fine borders, deliberate spacing, and flat technical controls keep the interface coherent. Avoid oversized rounded cards or ornamental skeuomorphism. Let depth concentrate in the computer stack, with working panels remaining visually stable.

## Typography

Use clean sans-serif type for navigation and instructions, with strong but restrained headline scale. Use monospace for code, pin names, binary values, layer numbers, and compact instrument labels. Prefer concrete terms—signals, gates, interface, test, verify—to fictional mission language.

## Workbench

The editable circuit and HDL are peers. Split view should expose the connection between a pin assignment and a wire without making either representation a small disclosure. Single visual and code views remain available, especially on narrow screens. A technical signal monitor shows current inputs and outputs; test evidence shows the complete contract.

Keep part controls, view controls, and test actions easy to identify. Invalid code is an ordinary working state with a concise diagnostic, not a destructive modal. Hints and conceptual explanations remain secondary to the construction surface.

## Reference

The reference uses the same dark technical surfaces and indigo selection states. The interactive models keep signals, expressions, and truth-table rows connected. Use source examples and diagrams without pretending they are new construction levels. Preserve the original source links and licensing.

## Accessibility and responsiveness

Native buttons provide stack and gate selection, mode switching, and wiring actions. Visible labels should match their accessible names. Focus must remain obvious on dark and light surfaces. Numerical and textual state accompany color. Responsive layouts must work at 320px without making the entire page overflow; a clearly bounded code or schematic surface may scroll internally.

Animations should explain selection or a real signal state. Honor reduced motion and keep sound optional. No decorative motion should compete with reading code or tracing a connection.
